# v0.2 OVAL-to-OSCAL mapping contract

The first usable-alpha mapping workflow makes control relationships explicit.
It does not infer that an OVAL identifier is an OSCAL control, objective, or
statement. A mapping is local JSON with this exact versioned envelope:

```json
{
  "format": "endeavor-oval-oscal-mapping",
  "version": "1.0.0",
  "oscal-version": "1.2.0",
  "mappings": []
}
```

Each entry has an `oval-definition-id`, one target (`objective-id` or
`statement-id`), and explicit `true` and/or `false` outcome semantics. The
author chooses `satisfied`/`not-satisfied` plus `pass`/`fail`/`other`; Endeavor
does not infer them from the definition class. Other OVAL statuses remain
observations only and are never collapsed into a finding.

Run the visibility report with:

```bash
python3 -m endeavor mapping-report \
  --results fixtures/oval-results/fail.xml \
  --definitions fixtures/oval-definitions/definitions.xml \
  --mapping fixtures/mappings/example-v1.json
```

The deterministic report includes safe basenames and hashes, mapped evaluated
IDs and targets, unmapped IDs with title/class/current result, and stale map
IDs absent from the supplied Definitions. Incomplete coverage is reported,
not treated as an error; a future `--require-complete-mapping` policy may make
that an enforcement gate. The initial alpha report intentionally excludes
source descriptions, evaluator messages, raw XML, system facts, and absolute
paths.

Render the same coverage data for human review with:

```bash
python3 -m endeavor report \
  --results fixtures/oval-results/fail.xml \
  --definitions fixtures/oval-definitions/definitions.xml \
  --mapping fixtures/mappings/example-v1.json \
  --output /tmp/endeavor-mapping-report.html
```

The report is static semantic HTML with headings, captions, table header
scopes, and a readable no-JavaScript presentation. Mapping and source text is
HTML-escaped; it retains only the safe report data, not raw XML or host paths.

`convert --mapping MAPPING` retains every source observation and adds a
schema-validated finding only for an explicit matching `true` or `false`
outcome. It records the mapping hash/version, original OVAL status, and source
observation UUID as namespaced finding properties. The pinned OSCAL 1.2.0 JSON
schema currently rejects the standard `related-observations.observation-uuid`
object because that object simultaneously requires the property and prohibits
all properties; Endeavor does not emit an invalid reference. Resolving that
upstream-schema defect is required before replacing the provenance property
with the standard relationship.
