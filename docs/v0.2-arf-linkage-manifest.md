# v0.2 ARF linkage manifest

OpenSCAP ARFs may contain OVAL Results/Definitions and Tailoring components
without source-level relationships that prove which component governed a report.
Endeavor accepts a separate, versioned authored manifest to supply that missing
association without heuristic matching.

Use it with:

```bash
python3 -m endeavor inspect-arf-linkage \
  --results fixtures/arf/openscap-1.4.4-tailoring-sanitized.arf.xml \
  --linkage fixtures/linkage/openscap-1.4.4-tailoring-v1.json
```

## Contract

The exact v1 JSON shape is demonstrated by the committed fixture. It requires:

- the raw ARF SHA-256;
- one exact `report-id` plus report-content C14N SHA-256;
- report-request, data-stream, component-reference, and component IDs;
- the full `ds:component` C14N SHA-256;
- for tailoring, the TestResult, Tailoring, and selected Profile IDs.

All JSON objects have exact keys; duplicate keys, unknown keys, symlinks,
oversized inputs, stale hashes, ambiguous references, wrong payload types, and
missing result definitions are rejected. Component hashes cover the complete
`ds:component` wrapper, while report hashes cover the one ARF report-content
payload; both use comment-free XML C14N.

## Semantics

The manifest is explicit authored provenance. It never fetches a URL or infers
an association from IDs, filenames, order, URLs, or matching hashes. A native
TestResult profile is checked when present; if OpenSCAP omitted it, the output
states `source-profile-confirmed: false`.

Resolution is not conversion. Embedded OVAL conversion remains unavailable
unless it supplies a complete Results and Definitions pair in Endeavor's pinned
OVAL 5.11 or 5.11.3 parser profiles. The committed ARF's Definitions component
lacks required generator metadata, so it is deliberately linkage-only.
Tailoring decision interpretation also remains unavailable until a dedicated,
validated Tailoring interpreter exists.
