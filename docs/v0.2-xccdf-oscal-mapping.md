# v0.2 XCCDF-to-OSCAL mapping contract

`endeavor-xccdf-oscal-mapping` v1 is an authored mapping inventory for
XCCDF rule results. It is intentionally separate from the OVAL mapping format.

```json
{
  "format": "endeavor-xccdf-oscal-mapping",
  "version": "1.0.0",
  "oscal-version": "1.2.0",
  "mappings": [{
    "benchmark-id": "xccdf_example_benchmark_baseline",
    "rule-id": "xccdf_example_rule_1",
    "target": {"type": "objective-id", "target-id": "ac-2.1_obj.1"},
    "outcomes": {
      "fail": {"state": "not-satisfied", "reason": "fail"}
    }
  }]
}
```

Each entry has exactly `benchmark-id`, `rule-id`, `target`, and `outcomes`.
Targets support `objective-id` and `statement-id`. Outcomes may name only the
literal XCCDF result vocabulary and must explicitly provide OSCAL state and
reason. Duplicate benchmark/rule/target entries are invalid.

Rules without a matching mapping, or without an authored outcome for their
current status, remain source evidence only. They create no finding or control
status. The same mapping applies to standalone XCCDF and ARF-embedded XCCDF;
ARF provides transport provenance, not a second mapping semantic. ARF embedded
OVAL remains unmapped until its Definitions linkage is authoritative.
