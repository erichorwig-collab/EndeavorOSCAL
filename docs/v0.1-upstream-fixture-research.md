# v0.1 upstream fixture research

Research date: 2026-08-29

## Result

No public upstream pair meeting all v0.1 requirements was found: an OVAL
Results document, its matching Definitions document, a core generator
declaration of `5.12` or `5.12.2`, and clear redistribution terms.

## Sources checked

- The [OVAL Community repository](https://github.com/OVAL-Community/OVAL)
  provides schemas and documentation. Its
  [v5.12](https://github.com/OVAL-Community/OVAL/releases/tag/v5.12) and
  [v5.12.2](https://github.com/OVAL-Community/OVAL/releases/tag/v5.12.2)
  releases contain schema and documentation archives, not an evaluated Results
  corpus.
- OVAL's [terms of use](https://github.com/OVAL-Community/OVAL/blob/master/terms-of-use.rst)
  permit reproduction and modification with the required disclaimer retained,
  but they do not provide a matching Results fixture.
- The official [OVAL content-repository guide](https://github.com/OVAL-Community/OVAL/blob/master/guidelines/oval-content-repos.rst)
  identifies definition feeds, not paired evaluation results.
- OpenSCAP's LGPL-2.1
  [`results-good.xml`](https://github.com/OpenSCAP/openscap/blob/main/tests/API/OVAL/results-good.xml)
  is a real 407,664-byte Results document, but declares core schema version
  `5.5`; it is outside Endeavor's supported range and is not vendored.

## Required fallback: sanitized generated pair

The acceptable fallback is a project-authored, reproducibly generated fixture,
not a relabeled synthetic document:

1. Run a documented evaluator version against a minimal, redistributable OVAL
   5.12/5.12.2 Definitions document.
2. Remove or replace host-identifying values, package inventories, IP/MAC
   addresses, usernames, serial numbers, and timestamps only when replacement
   preserves XSD validity and the evaluation result's meaning.
3. Preserve the source and sanitized output separately; record evaluator
   version, commands, source URL/license, retrieval date, SHA-256 values, and
   every sanitization transformation.
4. Re-run Endeavor's XML and OSCAL gates over the sanitized pair. Label it
   `generated-sanitized`, never `upstream-fixture`.

The current host has neither `oscap` installed nor permission to access the
available Docker daemon. The configured Arch repositories were also checked on
2026-08-29 and do not contain an `openscap` package. Generation therefore
awaits a user-authorized evaluator environment or an authorized sanitized
input pair.

## OpenSCAP compatibility constraint

OpenSCAP cannot generate the requested fallback pair for this contract: its
[1.4.3 release notes](https://github.com/OpenSCAP/openscap/blob/main/NEWS)
state that `OVAL_SUPPORTED` is 5.11.3. Running OpenSCAP in an authorized
container or host environment would therefore yield a real 5.11.3 result, not
the required 5.12/5.12.2 result. Endeavor must not relabel that output as
5.12-compatible.

The product decision now supports OVAL 5.11 and 5.11.3 with pinned schemas,
parser, and mapping coverage. OVAL 5.12/5.12.2 remains future-release work.
