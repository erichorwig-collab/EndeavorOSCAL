# v0.1 OVAL Results to OSCAL Assessment Results contract

## Scope

v0.1 converts one OVAL 5.12.2 Results document, with its source Definitions
document, into one OSCAL Assessment Results document. It is an evidence
adapter: OpenSCAP or another OVAL evaluator remains responsible for
collection and evaluation.

The converter must reject malformed or unsupported input, preserve the source
artifacts and their SHA-256 hashes, and emit schema-valid OSCAL. It must not
claim an OVAL definition is executable OSCAL logic.

## Required input and output

| Item | v0.1 requirement |
| --- | --- |
| OVAL Results | One local OVAL 5.12.2 Results XML document. |
| OVAL Definitions | One local Definitions XML document matching the evaluated definition identifiers. |
| Run metadata | Evaluator name/version, execution start time, and source paths; command line and target identity are optional but preserved when supplied. |
| OSCAL | Assessment Results JSON conforming to the pinned OSCAL schema version. |
| Evidence | Back-matter resources for both OVAL XML documents, each with an SHA-256 hash. |

No network retrieval occurs during conversion. External entities and remote
references are disabled.

The vendored 5.12.2 XSD release accepts OVAL core generator declarations
`5.12` and `5.12.2`; v0.1 rejects every other core declaration. This permits
the standard 5.12 generator value while keeping the supported schema family
explicit.

## Core mapping

Each evaluated OVAL definition becomes one OSCAL **observation** with
`type: discovery` and `methods: ["TEST"]`. A definition is not a finding,
control, or control objective by itself. Endeavor creates a finding only when
the caller provides an explicit, versioned OVAL-definition-to-OSCAL mapping.

| OVAL source | OSCAL destination | Rule |
| --- | --- | --- |
| Result document and run | `assessment-results.uuid`, `metadata`, `results[]` | Use deterministic UUIDs from documented normalized inputs; record start time and evaluator identity. |
| Definition identifier | Observation property `name: oval-definition-id`, `ns: https://endeavor.dev/ns/oval` | Never use it as `target-id` unless it is genuinely an OSCAL identifier. |
| Definition title, description, class, references | Observation title, description, namespaced properties, and links | Preserve source text and identifiers; do not rewrite security semantics. |
| Definition result | Observation property `oval-result` in the Endeavor OVAL namespace | Preserve the exact OVAL value. |
| Result message | Observation description or `oval-result-message` property | Preserve evaluator diagnostics without converting an error into a failure. |
| System identity | Namespaced observation properties for OS name/version, architecture, and primary host name; `subject` only when an OSCAL subject is resolvable | Do not invent an OSCAL asset UUID. |
| Platform system characteristics | Namespaced property naming each observed platform extension namespace | Preserve its presence as provenance only; do not infer controls/findings or embed raw collected values. |
| Results and Definitions XML | `back-matter.resources[]`, linked from each observation | Include media type, source filename, SHA-256, and a stable internal resource UUID. |

## Status preservation

OVAL result values are not collapsed. v0.1 preserves all six values in
`oval-result`:

| OVAL result | v0.1 OSCAL treatment |
| --- | --- |
| `true` | Observation evidence only; do not infer `satisfied`. |
| `false` | Observation evidence only; do not infer `not-satisfied`. |
| `unknown` | Preserve exactly. |
| `error` | Preserve exactly and retain the evaluator message. |
| `not evaluated` | Preserve exactly. |
| `not applicable` | Preserve exactly. |

When a future explicit mapping provides an OSCAL control objective, Endeavor
may add an objective status for `true` or `false`; the original OVAL value
remains mandatory provenance. Other OVAL states cannot be losslessly mapped
to OSCAL's satisfied/not-satisfied objective-status vocabulary.

## Acceptance criteria

- Every converted definition has its OVAL identifier, exact source status, and
  links to both source artifacts.
- Every output validates against the pinned OSCAL Assessment Results schema.
- The same normalized input, clock, and UUID strategy produce stable output.
- A missing definition, unsupported schema version, unresolved mapping, or
  malformed XML exits nonzero with an actionable diagnostic and no trusted
  partial artifact.
- The v0.1 corpus covers all six source states: `true`, `false`, `unknown`,
  `error`, `not evaluated`, and `not applicable`.

## Proof-of-concept boundary

The initial executable slice performs bounded reads of regular non-symlink
files, rejects `DOCTYPE` and `ENTITY` declarations, accepts only supported
namespace-qualified roots and declared schema versions, and writes converted
JSON atomically. It validates OVAL with vendored, hash-pinned 5.12.2 XSDs and
OSCAL with a vendored, hash-pinned Assessment Results schema through pinned
AJV. Document-provided schema locations remain ignored.
