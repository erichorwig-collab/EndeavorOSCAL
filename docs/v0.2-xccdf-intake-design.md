# XCCDF intake design - Phase 4 foundation

The first SCAP-expansion increment is inventory-only XCCDF 1.2 Results intake.
It will not create OSCAL findings or infer control mappings. It establishes the
shared secure SCAP parser boundary before ARF collection support.

Supported producer target: OpenSCAP 1.4.4 XCCDF 1.2.1, validated against the
restricted vendored XSD bundle recorded in `endeavor/schemas/MANIFEST.md`.
The future `inspect-xccdf --results FILE` command must retain only safe
inventory/provenance: benchmark and TestResult IDs, rule-result IDs/statuses,
selected profile, target facts, evaluator metadata, timestamps, SHA-256, and
safe filename. It must preserve `pass`, `fail`, `error`, `unknown`,
`notchecked`, and `notapplicable` without normalization loss.

Before enabling the command, add a sanitized, reproducible producer-backed
fixture; dedicated byte/element/depth limits measured against that fixture;
and hostile-input tests for DTD/entity, XInclude, unsafe schema hint, and
over-limit handling. ARF follows only after this normalized XCCDF model exists:
its first slice is a bounded collection manifest that rejects ambiguous result
components by default and preserves component hashes and tailoring links.
