# v0.2 cross-format evidence contract

This contract defines the minimum provenance that a future shared
OSCAL-evidence conversion surface must retain. It is intentionally an envelope,
not a control mapping or finding model.

| Source | Required identifiers | Required integrity/provenance | Meaning preserved |
| --- | --- | --- | --- |
| OVAL Results + Definitions | definition ID, source filenames | SHA-256 of Results and Definitions; generator data | Exact six-valued OVAL result |
| XCCDF Results | Benchmark ID, TestResult ID, rule-result ID, selected profile | source SHA-256; evaluator, target, identity, timing, tailoring reference when supplied | Exact XCCDF rule-result value and score lexical values |
| ARF | report ID, report-request ID, asset ID, local component ID | source SHA-256; comment-free C14N component hashes; explicit relationships | Literal embedded XCCDF/OVAL evidence and linkage status |

An evidence envelope must carry `format`, `source.path`, `source.sha256`, and
the relevant source identifiers unchanged. ARF relationship and local-component
resolution status are explicit fields; missing or ambiguous links must remain
missing or rejected, never inferred from identifier coincidence, URLs, or
content hashes.

Conversion rules:

1. Only an authored mapping may create an OSCAL finding or control/objective
   status.
2. OVAL/XCCDF result values remain source-namespaced properties even when an
   authored mapping creates a finding.
3. Raw evidence references use only safe filenames, hashes, and `#uuid` or
   equivalent controlled back-matter references; no remote fetch occurs.
4. Tailoring is linked only by an explicit TestResult `tailoring-file` reference.
   An embedded ARF Tailoring component alone remains unlinked evidence.

The current Phase 4 CLI commands (`inspect`, `inspect-xccdf`, and `inspect-arf`)
produce the source inventories needed for this envelope. A single OSCAL output
that combines XCCDF/ARF evidence remains a subsequent implementation step and
must have cross-format golden fixtures plus OSCAL schema validation.
