# v0.1 CLI contract

This contract applies to the supported OVAL 5.11.3 vertical slice.  It makes
handled failures safe to consume in an automation or a CI log without exposing
raw evidence or host paths.

## Commands

`endeavor inspect --results RESULTS --definitions DEFINITIONS` writes one JSON
inventory document to standard output.  Its `path` values are safe basenames,
not caller-supplied paths.

`endeavor convert --results RESULTS --definitions DEFINITIONS --output OUTPUT`
writes canonical Assessment Results JSON atomically.  It writes no standard
output on success.

Both commands accept `--format text` (default) or `--format json` for handled
diagnostics.  Diagnostics are always a single line on standard error.  JSON
diagnostics have this stable shape:

```json
{"error":{"code":"input-invalid","exit-code":3,"message":"..."}}
```

## Exit codes

| Code | Meaning | Stable diagnostic code |
| --- | --- | --- |
| 0 | Command completed. | none |
| 2 | Invalid CLI invocation. | `usage` |
| 3 | Input is missing, unsafe, malformed, or outside the supported OVAL profile. | `input-invalid` |
| 4 | The output artifact could not be written. | `output-failed` |
| 5 | Reserved for a future explicitly handled internal failure. | `internal` |

Endeavor never emits raw XML, secrets, or absolute paths in handled
diagnostics.  Existing outputs are replaced only after a complete successful
conversion; no output is created for invalid input.
