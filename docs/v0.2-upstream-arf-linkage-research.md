# Upstream ARF linkage research

This record documents why Endeavor does not yet convert embedded ARF OVAL
evidence or tailoring decisions. It was verified against OpenSCAP commit
[`c09abc323ef1ebfc6d34945256689848208bf425`](https://github.com/OpenSCAP/openscap/tree/c09abc323ef1ebfc6d34945256689848208bf425).

## OVAL Results to Definitions

OpenSCAP's
[`test_xccdf_overrides.arf.xml`](https://github.com/OpenSCAP/openscap/blob/c09abc323ef1ebfc6d34945256689848208bf425/tests/API/XCCDF/unittests/test_xccdf_overrides.arf.xml)
contains OVAL Definitions components and several OVAL Results reports. Its
only ARF relationships bind the XCCDF report to its report-request collection
and assessed asset. No relationship binds an OVAL Results report to one
Definitions component.

The ARF writer maps an OVAL result filename to an ARF report and rewrites an
XCCDF check-content reference to that report, but this is not a
Results-to-Definitions relationship. See
[`rds.c`](https://github.com/OpenSCAP/openscap/blob/c09abc323ef1ebfc6d34945256689848208bf425/src/DS/rds.c#L425-L480)
and
[`rds.c`](https://github.com/OpenSCAP/openscap/blob/c09abc323ef1ebfc6d34945256689848208bf425/src/DS/rds.c#L777-L790).

Endeavor therefore keeps each embedded OVAL definition ID, result value, and
canonical report hash as unlinked evidence. Matching IDs, component order,
URLs, or content hashes are not authoritative provenance.

## Tailoring to TestResult

OpenSCAP's
[`tailoring test`](https://github.com/OpenSCAP/openscap/blob/c09abc323ef1ebfc6d34945256689848208bf425/tests/API/XCCDF/tailoring/all.sh#L87-L148)
generates an ARF from an external tailoring file and asserts that a Tailoring
component and data-stream component reference are embedded. The ARF writer
does not serialize a TestResult `tailoring-file` reference; its relevant
behavior only embeds the component and reference in the data stream. See
[`rds.c`](https://github.com/OpenSCAP/openscap/blob/c09abc323ef1ebfc6d34945256689848208bf425/src/DS/rds.c#L711-L767).

An embedded component proves availability, not that the evaluated TestResult
used it. Endeavor consequently retains it as unlinked inventory and does not
derive tailoring decisions.

## Safe future path

Either of the following can establish the missing provenance:

1. An upstream producer version that serializes unique, local ARF
   Results-to-Definitions and TestResult-to-Tailoring relationships.
2. A separately versioned, SHA-256-bound authored linkage manifest supplied
   with the ARF. The manifest must identify exactly one local component per
   OVAL report and/or TestResult, and Endeavor must reject missing, stale, or
   ambiguous entries.

Endeavor implements option 2 as the provenance-only
[ARF linkage manifest](v0.2-arf-linkage-manifest.md). It does not itself add
OVAL schema support or a tailoring-decision interpreter; until those exist,
the linked-ARF XCCDF converter remains the supported ARF-to-OSCAL path.
